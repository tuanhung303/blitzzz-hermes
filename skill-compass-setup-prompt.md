# Task: Setup the Central Skill Registry with Skill Compass and OKF Catalog

You are tasked with establishing a unified, catalogued Agent Skills system using the Open Knowledge Format (OKF v0.2) and the Skill Compass discovery/maintenance pattern.

## 1. System Goals and Architecture

A flat list of skills causes discovery failure and rot. The architecture separates the **payloads** (`SKILL.md` files), the **curated intelligence** (`_facets.yaml`), and the **deterministic catalog view** (`.okf/` bundle generated by script).

### Directory Layout to Create

```text
skills/
├── <skill-a>/
│   └── SKILL.md
├── <skill-b>/
│   └── SKILL.md
├── skill-compass/
│   └── SKILL.md                  # Companion skill teaching agents how to use the catalog
├── .okf/
│   ├── index.md                  # Root OKF index (grouped by domain, summary <=120 chars)
│   ├── by-task.md                # Intent-shaped entry point (task clusters)
│   ├── log.md                    # Immutable mutation log (capped, dated entries)
│   ├── _facets.yaml              # Curated manual layer (alternatives, prereqs, clusters)
│   └── skills/                   # Concept files (one markdown file per skill)
│       ├── <skill-a>.md
│       └── <skill-b>.md
├── scripts/
│   ├── gen_catalog.py            # Python generator script (uv-runnable)
│   └── skill-maintenance.sh      # Daily async drift/archive/commit automation
└── setup-symlinks.sh             # Symlinks shared skills into agent harnesses
```

## 2. File Specifications and Schemas

### A. Individual Skill Payloads (`skills/<name>/SKILL.md`)
Standard Agent Skill structure with YAML frontmatter:

```markdown
---
name: <skill-name>
description: Clear, trigger-rich description of when and why to use this skill.
version: 0.1.0
---

# <skill-name>

Instructions, guidelines, workflows, and tools for this skill.
```

### B. Curated Facets Layer (`skills/.okf/_facets.yaml`)
This non-markdown file contains domain knowledge that cannot be extracted automatically from `SKILL.md` alone. The generator preserves and merges this file during regeneration.

```yaml
task_clusters:
  - id: analysis
    title: "Data Analysis & Verification"
    skills: [data-checker, reconciliation]
  - id: design
    title: "Visual Design & UI"
    skills: [ui-taste, arch-drawing]

alternatives:
  - use: modern-tool
    instead_of: [legacy-tool]
    note: "legacy-tool is deprecated; modern-tool handles all current workflows"

prereqs:
  - skill: specialized-workflow
    requires: [base-analyzer]

aliases:
  - skill: data-checker
    alias: [verify-data, check-db]

tags_extra:
  - skill: data-checker
    tags: [sql, postgres, validation]
```

### C. OKF Concept Schema (`skills/.okf/skills/<name>.md`)
Each skill is represented as an OKF concept file generated by `gen_catalog.py`:

```markdown
---
type: skill
title: <Human Display Title>
name: <relative-path-identifier>
description: <verbatim description from SKILL.md>
version: <version>
tags: [<tag1>, <tag2>]
resource: ../../<name>/SKILL.md
skill_status: stable             # stable | deprecated | orphaned
linked: true                     # true if deployed in setup-symlinks.sh
source_sha256: <hash>
generated:
  by: process:skill-compass-gen
  at: '2026-08-21T12:00:00+00:00'
---

# Summary
<description>

# How to load
Read the payload file at [SKILL.md](../../<name>/SKILL.md).

# Related
- Alternative to: ...
- Requires: ...

[^src]: Derived from [SKILL.md](../../<name>/SKILL.md).
```

### D. Root Catalog (`skills/.okf/index.md`)
Frontmatter contains strictly `okf_version: "0.2"`. The body contains domain sections with truncated summaries (max 120 chars) linking to individual concept files.

## 3. Catalog Generator (`skills/scripts/gen_catalog.py`)

Implement `gen_catalog.py` (Python 3.11+, using `pyyaml`) with the following CLI modes:
- `regen` (default): Scans all directories containing `SKILL.md`, compares SHA-256 hashes, parses frontmatter, merges `_facets.yaml`, updates changed concept files, regenerates `index.md` and `by-task.md`, and logs changes to `log.md`.
- `check`: Validates consistency between real `SKILL.md` directories and `.okf/` concepts. Returns exit code `1` on actionable drift (missing concepts, stale hashes, broken references).
- `add <name>`: Adds or refreshes a single concept.
- `remove <name> [--superseded-by <other>] [--force]`: Marks a concept as `deprecated` (or removes it if `--force` is used and the directory is already deleted).
- `archive [--grace-days 30] [--purge-after 90]`: Moves deprecated skills older than the grace period into `archive/` and purges expired archives.

## 4. Companion Skill: `skill-compass` (`skills/skill-compass/SKILL.md`)

Create `skills/skill-compass/SKILL.md` to instruct agents how and when to use the catalog:

```markdown
---
name: skill-compass
description: >-
  Use when the injected skill list has no clear match, when requirements change and you need to
  expand to relevant skills, or when adding/updating/removing a skill in the central registry.
  Points to the OKF catalog at .okf (index.md -> by-task.md -> concepts) and gen_catalog.py.
version: 0.1.0
---

# skill-compass

The central skill registry is mirrored as an OKF bundle at `.okf/`:
- `index.md`: Grouped catalog with status badges (`deprecated`, `unlinked`).
- `by-task.md`: Intent-shaped entry point for task clusters.
- `log.md`: Change history.

## Discovery Workflow (Read-Only)
1. Read `.okf/index.md` or `.okf/by-task.md` when intent is cluster-based.
2. Follow links to the relevant concept file under `.okf/skills/`.
3. Check `status`, `related_skills`, and load the target payload from `resource:`.
4. Treat `status: deprecated` or past `stale_after` as "verify before relying".

## Maintenance Workflow
- Add skill: Create `skills/<name>/SKILL.md` -> run `uv run scripts/gen_catalog.py` -> validate.
- Update skill: Edit `skills/<name>/SKILL.md` -> run `uv run scripts/gen_catalog.py` -> validate.
- Remove skill: Run `uv run scripts/gen_catalog.py remove <name> --superseded-by <replacement>`.
```

## 5. Global Agent Instruction / Rule Injection

Add the following rule to your workspace `AGENTS.md`, `CLAUDE.md`, or global prompt:

```markdown
## Skill Compass First Rule

Before starting non-trivial tasks:
1. Consult `skills/skill-compass/SKILL.md` as the entry point.
2. Search the OKF catalog at `skills/.okf/`:
   - `index.md`: Catalog grouped by domain.
   - `by-task.md`: Intent-shaped task clusters.
3. Inspect concept files and load the designated `resource:` path.
4. If a skill is updated or added, always run `uv run scripts/gen_catalog.py` to keep the catalog in sync.
```

---

## 6. Execution Steps for the Setup Agent

1. Scaffold the directory tree: `mkdir -p skills/.okf/skills skills/scripts skills/skill-compass`.
2. Author `skills/.okf/_facets.yaml` with initial clusters and relationships.
3. Write `skills/scripts/gen_catalog.py` supporting `regen`, `check`, `add`, and `remove`.
4. Populate existing or initial `SKILL.md` files across domain subdirectories.
5. Create `skills/skill-compass/SKILL.md`.
6. Run `python3 skills/scripts/gen_catalog.py` to generate `.okf/index.md`, `.okf/by-task.md`, and all concept files.
7. Inject the "Skill Compass First" rule into the root agent configuration (`AGENTS.md` / `CLAUDE.md`).
